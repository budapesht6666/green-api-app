# Telegram-чат на GREEN-API

Веб-интерфейс для отправки и получения текстовых сообщений Telegram через [GREEN-API](https://green-api.com/telegram). React 19 + TypeScript + Vite.

- **Приложение онлайн:** https://greenchat.p1gog.duckdns.org
- **О проекте (демо-видео, скриншоты):** https://greenchat.p1gog.duckdns.org/about/
- **Инструкция по локальному запуску:** [docs/local-setup.md](docs/local-setup.md)

## Как попробовать

1. В [личном кабинете GREEN-API](https://console.green-api.com) создайте Telegram-инстанс (тариф «Разработчик» бесплатный) и авторизуйте его: Telegram → Настройки → Устройства → Подключить устройство, затем «Получить QR» у инстанса.
2. Откройте приложение и введите `idInstance` и `apiTokenInstance` инстанса.
3. Нажмите «+» и введите номер получателя (у него должен быть Telegram) — чат появится в списке.
4. Напишите сообщение. Ответ получателя из Telegram появится в чате в течение нескольких секунд.

Если над чатом появилась жёлтая плашка «выключены уведомления» — нажмите «Включить уведомления» (инстанс перезапустится, это занимает до 5 минут).

Если сообщение не ушло (нет связи, ошибка API), под ним появится кнопка «Повторить». Если хост вашего инстанса не совпадает с `https://{первые 4 цифры idInstance}.api.green-api.com`, на экране входа можно указать `apiUrl` из кабинета («Свой адрес API»).

> Тариф «Разработчик»: 3 чата и 100 проверок номеров.

## Как это работает

| Действие | Метод GREEN-API |
|---|---|
| Проверка входа | `getStateInstance` |
| Номер → chatId | `checkAccount` |
| Отправка текста | `sendMessage` |
| Получение сообщений | `receiveNotification` + `deleteNotification` (HTTP API, long polling) |

Бэкенда нет: браузер обращается к GREEN-API напрямую. Учётные данные хранятся только в `sessionStorage` вкладки, история переписки — в `localStorage`.

## Принятые решения

- **Long polling, а не webhook.** Webhook требует публичного HTTP-эндпоинта, то есть бэкенда, а браузер его поднять не может; кроме того, ТЗ называет именно HTTP API. Цикл: `receiveNotification` (ожидание до 20 с) → обработка → `deleteNotification`. Уведомление удаляется только после обработки, поэтому при обрыве оно придёт повторно, а дубли отсекаются по `idMessage`. Запросы имеют клиентский таймаут, зависшее соединение не останавливает приём; при ошибке — пауза 3 с и повтор.
- **Номер → `chatId` через `CheckAccount`.** В Telegram-версии GREEN-API `chatId` не равен номеру телефона; отправляем только по `chatId` (так рекомендует документация). Для уже созданных чатов повторная проверка не делается, чтобы не тратить квоту (100 проверок на тарифе «Разработчик»).
- **`useReducer` вместо стейт-менеджера.** Вся логика чатов (дедупликация, монотонность статусов, гонка между ответом `SendMessage` и уведомлением о том же сообщении, непрочитанные) — одна чистая функция [chatReducer](src/state/chatReducer.ts) с тестами. Локальное состояние форм остаётся в компонентах.
- **Минимум зависимостей.** В runtime только `react` и `react-dom`: клиент API на `fetch`, нормализация номера и стили (CSS Modules) без библиотек.
- **Сбои хранилища не ломают приложение.** Повреждённая запись истории отбрасывается, переполнение квоты `localStorage` даёт предупреждение в консоли (без данных), токен хранится только в `sessionStorage`.
- **Только текст.** Остальные типы уведомлений и сообщения групп игнорируются, но всегда удаляются из очереди, чтобы она не застревала.
